# Sion Bible 페이지 완성도 감사

검토 기준 브랜치: `agent/page-completion-wave-2`

## 감사 원칙

- 파일 존재 여부만으로 완료 처리하지 않는다.
- 사용자 진입 경로, 저장·복원, 오류 상태, 모바일 안전 영역, 접근 가능한 버튼을 함께 확인한다.
- 외부 서비스 결제·권한 문제와 애플리케이션 코드 결함을 분리한다.
- 대규모 개선은 한 번에 병합하지 않고 검증 가능한 웨이브 단위로 진행한다.

## Wave 1에서 해결한 결함

### 성경책과 장 선택의 원자적 갱신

기존 구현은 성경책 상태를 갱신한 직후 별도의 장 선택 콜백에서 이전 렌더의 성경책 상태를 읽을 수 있었다. 그 결과 화면 본문은 새 책으로 바뀌더라도 외부에 저장되는 마지막 읽기 위치가 이전 성경책으로 기록될 가능성이 있었다.

수정 내용:

- `BibleBookChapterSelector`가 `(book, chapter)`를 하나의 `onSelectReference` 콜백으로 전달한다.
- `BibleVersePicker`가 전달받은 동일한 책·장으로 내부 상태와 외부 탐색 상태를 함께 갱신한다.
- `scripts/audit-bible-navigation.mjs`를 추가해 이전의 분리 콜백과 오래된 상태 참조가 다시 들어오면 빌드가 실패하도록 했다.

## Wave 2에서 완성한 화면

### 통독 코스 상세

- 선택한 코스의 기간, 하루 분량, 보상, 진행률, 오늘 본문을 표시한다.
- 코스 시작, 이어 읽기, 오늘 미션으로 연결한다.
- 선택한 코스 ID를 저장해 새로고침 뒤에도 동일한 상세 화면을 복원한다.

### 오늘의 통독 미션

- 오늘 읽을 장을 체크리스트로 펼쳐 표시한다.
- 본문 읽기와 완료 처리를 연결한다.
- 마지막 날 완료 시 통독 완료 화면으로 이동한다.

### 통독 완료

- 완주 코스, 읽은 분량, 연속 일수, 포인트와 배지를 요약한다.
- 다음 추천 코스 시작과 나의 코스 복귀를 연결한다.

### 탐색 정리

- 상세·완료 화면에서는 하단 탭을 숨겨 중복 탐색을 방지한다.
- 하위 화면은 자체 뒤로가기·공유 헤더를 사용한다.
- `scripts/audit-reading-room-routes.mjs`로 세 경로와 화면 렌더링이 다시 제거되지 않도록 검사한다.

## 현재 코드 밖의 차단 요소

1. GitHub Actions 작업은 계정 결제 또는 Actions 지출 한도 문제로 실행 전에 중단된다. 코드 빌드 실패와 별개다.
2. Vercel에 이름이 유사한 프로젝트가 둘 있어 운영 프로젝트 정리가 필요하지만, 삭제는 복구가 어려우므로 별도 승인 없이 수행하지 않는다.
3. 오래된 대형 Draft PR은 현재 `main`과 겹치는 변경이 많아 일괄 병합하지 않고 기능별로 재검토한다.

## 플러그인 오케스트레이션

| 단계 | 사용 도구 | 역할 |
| --- | --- | --- |
| 저장소 감사·수정·PR | GitHub | 파일 구조, 리뷰 지적, 브랜치, 커밋, PR, 병합 |
| React 상태 검증 | Context7 | 최신 React 문서 기준으로 상태 스냅샷·배치 동작 교차검증 |
| 빌드·미리보기·운영 배포 | Vercel | GitHub Actions가 막힌 동안 독립적인 빌드 검증과 배포 상태 확인 |
| 실패 로그 구조화 | Error Log Parser | Vercel 또는 런타임 오류가 발생할 때만 사용 |
| UI 원본 개선 | Figma·Adobe·Canva | 기능 결함이 정리된 후 디자인 웨이브에서 선택 사용 |
| 데이터·동기화 | Supabase·Neon·Convex | 로컬 전용 데이터를 계정 동기화로 확장할 때 설계 후 사용 |
| 영상·콘텐츠 | Remotion·HyperFrames·HeyGen 등 | 앱 핵심 페이지 완성과 별개인 콘텐츠 제작 웨이브에서 사용 |

사용 목적이 없는 플러그인을 동시에 호출하지 않는다. 각 웨이브에서 결과를 검증할 수 있는 도구만 선택한다.
