# Sion Bible 페이지 완성도 감사

검토 기준 브랜치: `agent/page-completion-wave-7`

## 감사 원칙

- 파일 존재 여부만으로 완료 처리하지 않는다.
- 사용자 진입 경로, 저장·복원, 오류 상태, 모바일 안전 영역, 접근 가능한 버튼을 함께 확인한다.
- 외부 서비스 결제·권한 문제와 애플리케이션 코드 결함을 분리한다.
- 개선은 검증 가능한 웨이브 단위로 진행하고 매 웨이브를 Vercel Preview로 빌드한다.

## Wave 1 — 본문 탐색 상태 정합성

- 책과 장을 `(book, chapter)` 하나의 콜백으로 갱신한다.
- 새 책을 선택한 직후 이전 책이 마지막 읽기 위치로 저장되는 상태 스냅샷 오류를 제거했다.
- `audit-bible-navigation.mjs`가 오래된 분리 콜백과 이전 상태 참조를 차단한다.

## Wave 2 — 통독 하위 화면

- `/reading-room/course-detail`: 기간, 분량, 보상, 진행률, 시작·이어 읽기·미션 진입.
- `/reading-room/mission`: 장별 체크, 본문 읽기, 완료, 마지막 날 완주 전환.
- `/reading-room/course-complete`: 완주 결과, 포인트, 연속 일수, 분량, 배지와 다음 코스.
- 선택 코스를 저장하고 하위 경로의 헤더·하단 탐색을 정리했다.
- `audit-reading-room-routes.mjs`가 세 경로와 화면 렌더링을 검사한다.

## Wave 3 — 암송 알림 예약 엔진

- 지정 시간 알림과 하루 1·3·5회 균등 배분을 구현했다.
- 자정을 넘는 활동 시간과 자동 복습 간격 일정을 처리한다.
- 앱 시작·포커스·화면 복귀·저장소 변경 시 예약을 복구한다.
- 서비스 워커 알림, 브라우저 대체 알림과 클릭 후 암송 탭 복귀를 연결했다.
- 테스트 알림, 권한 거부 안내, 다음 알림 미리보기를 제공한다.
- `audit-memory-reminders.mjs`가 세 모드와 PWA 연결을 검사한다.

현재 범위는 로컬 PWA 예약이다. 앱 완전 종료 중 확정 발송에는 VAPID 키, Push 구독 DB와 서버 Cron이 필요하다.

## Wave 4 — 통독 묵상과 포인트 상점

- 무반응이던 `묵상하기`를 날짜·본문 기준 기록창으로 연결했다.
- 저장·불러오기·수정, 빈 내용 방지, 저장 상태와 모바일 접근성을 구현했다.
- 포인트 잔액, 부족 안내, 구매 저장, 재구매 방지, 구매 완료와 차감 내역을 구현했다.
- DOM 변경 감시에서 내역이 반복 생성되지 않도록 상태 서명을 사용한다.
- `audit-reading-room-actions.mjs`가 묵상과 구매 계약을 검사한다.

## Wave 5 — 통합 데이터 백업·복원

- `gb_*`, `sion_*` 등 앱 관리 데이터만 JSON으로 내보낸다.
- 저장 말씀, 묵상, 암송, 복습 일정, 통독, 포인트, 테마·글자·마지막 읽기 위치를 포함한다.
- 토큰, 비밀번호, API 키, 인증 정보로 보이는 키는 제외한다.
- 형식·버전·출처·시간대와 FNV-1a 체크섬을 기록한다.
- 5MB 제한, JSON 구조, 허용 키, 문자열 값과 체크섬을 복원 전에 검사한다.
- 복원 직전 세션 롤백 사본을 만들고 마지막 복원 되돌리기를 제공한다.
- `audit-data-backup.mjs`가 내보내기, 검증, 민감정보 제외와 롤백을 검사한다.

## Wave 6 — 무반응 버튼 전수 감사

- TypeScript AST로 `src/**/*.tsx`의 모든 `<button>`을 스캔한다.
- 직접 이벤트, 폼 동작, 비활성 상태, 스프레드 속성 또는 검증된 위임이 없으면 빌드가 실패한다.
- 직접 핸들러가 없던 묵상 버튼과 상품 버튼은 실제 위임 모듈의 모달·저장 동작까지 검증한다.
- 실제 무반응이었던 통독 도움말에는 경로별 이용 안내 모달을 구현했다.
- `audit-interactive-buttons.mjs`가 전체 TSX에서 남은 무계약 버튼이 없음을 보장한다.

## Wave 7 — AI 장애·오프라인·빈 응답

### 공통 오류 분류

- 오프라인, 시간 초과, 사용량 제한(429), 인증·권한(401·403), 공급자 오류(5xx), 빈 응답과 일반 네트워크 오류를 구분한다.
- 각 상태에 사용자용 제목, 원인 설명, 재시도 가능 여부를 부여한다.
- AI 요청 응답의 핵심 텍스트가 비어 있으면 성공으로 처리하지 않는다.

### 전역 AI 상태 화면

- 묵상, 질문, AI 검색, 통독 묵상과 연결 점검 API를 중앙에서 관찰한다.
- 오프라인이면 원격 요청을 시작하지 않고 로컬 성경과 저장된 묵상을 계속 사용할 수 있음을 안내한다.
- 실패 상태는 접근성 알림으로 표시하고 `다시 시도`, `연결 확인`, `나중에` 동작을 제공한다.
- 온라인·오프라인 전환을 감지해 연결 복구 시 안내를 자동 해제한다.

### 묵상 질문

- 오프라인 상태에서는 요청을 즉시 중단한다.
- 빈 AI 답변을 오류로 처리한다.
- 오류 종류별 제목과 설명을 보여주고 동일 질문을 재시도한다.
- 전역 재시도 이벤트와 화면 내부 재시도 버튼을 모두 지원한다.

### 기존 로컬 대체 흐름

- AI 묵상 생성 실패 시 기존의 문맥 기반 로컬 묵상을 계속 표시한다.
- 질문 검색은 기존 오류·빈 결과 화면을 유지하면서 전역 상태 분류 안내를 함께 제공한다.
- `audit-ai-resilience.mjs`가 분류, 전역 관찰, 온라인 전환, 빈 답변, 재시도와 로컬 대체를 검사한다.

## 남은 성능·운영 항목

- 메인 JavaScript 청크 약 643KB: 라우트·기능별 코드 분할 필요.
- `app-book-background` 이미지 약 1.4MB: WebP·AVIF 변환과 반응형 로딩 필요.
- 일부 동적 import가 정적 import와 중복되어 청크 분리에 기여하지 못한다.
- GitHub Actions는 계정 결제 또는 Actions 지출 한도 문제로 작업 시작 전에 중단된다.
- Vercel에 이름이 유사한 프로젝트가 둘 있어 운영 프로젝트 정리가 필요하지만 삭제는 승인 없이 수행하지 않는다.
- 확정 백그라운드 Web Push는 구독 DB, VAPID 키와 서버 Cron이 필요하다.
- iOS·Android 실기기의 설치, 권한과 완전 종료 상태는 실제 기기 검증이 필요하다.

## 플러그인 오케스트레이션

| 단계 | 사용 도구 | 역할 |
| --- | --- | --- |
| 저장소 감사·수정·PR | GitHub | 파일, 브랜치, 커밋, 리뷰, PR과 병합 |
| React 상태 교차검증 | Context7 | 상태 스냅샷·배치 동작 검증 |
| 독립 빌드·배포 검증 | Vercel | Billing으로 막힌 GitHub Actions 대신 Preview·Production 검증 |
| 오류 구조화 | Error Log Parser | 런타임·배포 로그의 구조화가 필요할 때 사용 |
| UI 원본 개선 | Figma·Adobe·Canva | 기능 결함 정리 후 디자인 웨이브에서 사용 |
| 계정 동기화·Push 저장 | Supabase·Neon·Convex | 서버 데이터가 필요한 웨이브에서 사용 |
| 영상·콘텐츠 | Remotion·HyperFrames·HeyGen 등 | 핵심 앱과 분리된 콘텐츠 제작에서 사용 |

목적이 없는 플러그인을 동시에 호출하지 않고 각 웨이브 결과를 검증할 수 있는 도구만 사용한다.
